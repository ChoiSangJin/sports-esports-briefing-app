# 데이터 제공처와 모델 조사 — 2026-10-27

## LoL: 일반 게임 API와 프로대회 일정은 다릅니다

[Riot 공식 LoL 개발자 문서](https://developer.riotgames.com/docs/lol)는 플레이어 게임 기록, 랭크, 토너먼트 운영 API 등을 설명합니다. 이 문서에서 모든 프로대회의 일정·시리즈 스코어를 무료 공개하는 개발자용 엔드포인트는 확인하지 못했습니다. 일반 Riot 개발자 키를 프로대회 일정 키로 간주하지 않습니다.

대신 [LoL e스포츠 공식 일정](https://lolesports.com/ko-KR/schedule)이 로그인 없이 공개하는 응답에 경기 ID, UTC 시작 시간, 리그, 팀, 세트 승수, 시리즈 상태, Bo1/3/5, 세트별 진행 상태가 포함돼 있음을 실제로 확인했습니다. 이 버전은 그 페이지의 JSON 객체만 파싱합니다. 페이지 스크립트를 실행하거나 웹사이트용 API 키를 추출·하드코딩하지 않습니다.

현재 공식 페이지에는 최근 경기와 예정 경기의 한정된 묶음이 포함됩니다. 기기 현지 날짜로 필터링하고, 중복 SSR 객체는 경기 ID로 합칩니다. LCK만으로 제한하지 않으며 공식 페이지에 공개된 여러 지역 리그와 국제대회를 표시합니다. 페이지 데이터가 제공한 기간 밖 날짜는 조회 범위 안내를 표시합니다. 전체 역사 데이터를 보장하지 않습니다. 수동 새로고침 시 60초 페이지 캐시를 비웁니다. 구조가 바뀌면 오류를 표시하고 공식 페이지에서 확인할 수 있게 합니다.

이전 Fandom Cargo 요청은 접근 거부를 반환했습니다. `wiki.leagueoflegends.com/en-us/api.php`도 실제 조회에서 `cargoquery`를 지원하지 않아, 주소만 바꿔 Cargo 요청을 계속 보내는 방식은 채택하지 않았습니다.

## KBO: 공식 사이트가 사용하는 경기 JSON

[KBO 공식 게임센터](https://www.koreabaseball.com/Schedule/GameCenter/Main.aspx)는 `/ws/Main.asmx/GetKboGameList`를 사용합니다. 공식 페이지의 AJAX 호출과 동일하게 POST 폼 `leId`, `srId`, `date`, `Referer`, `X-Requested-With`를 보내자 정상 JSON(`code=100`, `game`)이 반환됐습니다. 기존 단순 HTML 조회에서는 경기가 JavaScript로 로드되어 비어 있거나 오류 HTML이 반환됐습니다.

앱은 이 공식 공개 응답을 사용합니다. 외부 개발자용으로 문서화·보장된 독립 API라고 주장하지는 않습니다. 정상 경기 목록이 빈 경우와 HTML 오류·응답 구조 변경·날짜 불일치를 구분합니다. 한국 시간의 경기 시작 시각을 파싱한 뒤 기기 날짜로 필터링하며, 현지 하루와 겹치는 KST 날짜를 조회합니다. 예정/취소 경기는 제공처의 초기 0점을 실제 결과처럼 표시하지 않습니다. 완료 경기에서만 승자를 강조합니다. 예시 경기는 사용자 일정에 삽입하지 않습니다.

실제 확인: 2026-10-26 KIA 5–1 삼성 종료 경기와 2026-10-27 18:30 KST KIA–삼성 예정 경기를 조회했습니다. API 응답에서 시간·상태·점수와 경기 ID를 교차 확인했습니다. 이 관측이 이후 날짜의 제공처 가용성을 보장하는 것은 아닙니다.

## Google AI Studio: 2.5 전용이 아닙니다

[Google 모델 문서](https://ai.google.dev/gemini-api/docs/models)는 여러 최신 모델을 안내합니다. 조사 시점 문서는 새 프로젝트에 3.5 Flash-Lite 또는 3.8 Flash를 안내하며, 2.5는 과거 사용 이력이 있는 사용자 중심으로 접근을 제한할 수 있다고 설명합니다. 2.5에만 고정된 것은 이전 앱의 하드코딩이었습니다.

[공식 Models REST 문서](https://ai.google.dev/api/models) 및 [공식 API 정의](https://github.com/googleapis/googleapis/blob/master/google/ai/generativelanguage/v1beta/model_service.proto)에 따라 `GET /v1beta/models`의 페이지를 모두 읽고 `supportedGenerationMethods`에 `generateContent`가 있는 모델을 표시합니다. 이름에 명시된 이미지·오디오·TTS·임베딩 전용 모델은 제외합니다. 모델 이름과 메서드만으로 실제 계정 권한·과금·모든 출력 형식을 확정할 수는 없으므로, 저장 전 선택 모델로 실제 생성 테스트를 수행합니다.

Gemini REST를 직접 사용하고, 키는 URL 쿼리가 아닌 `x-goog-api-key` 헤더로 전달합니다. 키는 검증 성공 뒤 Android 보안 저장소에 저장합니다. 조회된 모델 메타데이터만 일반 설정에 캐시하며 키는 캐시에 넣지 않습니다. 수동 ID 입력은 미리보기·새 모델에도 대응하지만, 지원하지 않는 모델의 오류와 할당량 오류는 사용자에게 구분해 알립니다. 자동으로 다른 유료 모델로 전환하지 않습니다.

실제 사용자 Gemini 키는 이 클라우드에 제공되지 않았으므로 실제 키의 모델 접근·생성 결과는 단정하지 않습니다. REST 응답·페이지네이션·키 저장 흐름·모델 선택은 주입된 테스트 응답으로 검증합니다.
